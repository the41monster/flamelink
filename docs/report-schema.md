# Report Schema

Flamelink's report schema defines the structure and format of reports generated by the system. It ensures consistency and standardization across different types of reports, making it easier for users to interpret and analyze the data presented.

---

## 1. Field reference

### Report

| Field | Type | Meaning |
|---|---|---|
| `timestamp` | string, date-time | The date and time when the report was generated (in UTC). |
| `target` | string | The URL that received load requests. |
| `duration_s` | number, > 0 | Requested run length in seconds. |
| `sampler` | `"py-spy"`, `"clinic"` or `null` | The profiler used. `null` for a load-only run. |
| `p50_ms`, `p95_ms`, `p99_ms` | number, >= 0 or `null` | The 50th, 95th, and 99th percentile response times in milliseconds. `null` if no request succeeded. |
| `hotspots` | array of `Hotspot` | The list of hotspots identified in the report. Empty for a load-only run. |

### Hotspot
| Field | Type | Meaning |
|---|---|---|
| `fn` | string | Function name |
| `file` | string or `null` | Source file name. |
| `line` | integer >= 1 or `null` | Line number where the function is defined. |
| `self_pct` | number, 0-100 | Share of samples in which the function was the one executing (the innermost frame on the stack). |
| `total_pct` | number, 0-100 | Share of samples in which the function is present anywhere in the call stack, counted once per sample. |

Every field is required, including the nullable ones.

## 2. JSON Schema

```json
{
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "$id": "report.schema.json",
    "title": "Load or profiling report",
    "type": "object",
    "additionalProperties": false,
    "required": [
        "timestamp",
        "target",
        "duration_s",
        "sampler",
        "p50_ms",
        "p95_ms",
        "p99_ms",
        "hotspots"
    ],
    "properties": {
        "timestamp": {
            "description": "The date and time when the report was generated (in UTC).",
            "type": "string",
            "format": "date-time"
        },
        "target": {
            "description": "The URL that received load requests.",
            "type": "string"
        },
        "duration_s": {
            "description": "Requested run length in seconds.",
            "type": "number",
            "exclusiveMinimum": 0
        },
        "sampler": {
            "description": "Profiler used, or null for load-only runs.",
            "enum": ["py-spy", "clinic", null]
        },
        "p50_ms": { "$ref": "#/$defs/percentile" },
        "p95_ms": { "$ref": "#/$defs/percentile" },
        "p99_ms": { "$ref": "#/$defs/percentile" },
        "hotspots": {
            "description": "Sorted by self_pct, descending. Empty for a load-only run.",
            "type": "array",
            "items": { "$ref": "#/$defs/hotspot" }
        }
    },
    "$defs": {
        "percentile": {
            "description": "Latency percentile in milliseconds, or null if no request succeeded.",
            "type": ["number", "null"],
            "minimum": 0
        },
        "pct": {
            "type": "number",
            "minimum": 0,
            "maximum": 100
        },
        "hotspot": {
            "description": "One function from the profile, identified by (fn, file, line).",
            "type": "object",
            "additionalProperties": false,
            "required": ["fn", "file", "line", "self_pct", "total_pct"],
            "properties": {
                "fn": {
                    "description": "Function name",
                    "type": "string"
                },
                "file": {
                    "description": "Source file name, or null if the frame has none",
                    "type": ["string", "null"]
                },
                "line": {
                    "description": "Line number where the function is defined, or null if unknown",
                    "type": ["integer", "null"],
                    "minimum": 1
                },
                "self_pct": {
                    "description": "Percentage of samples in which the function was the one executing (the innermost frame on the stack).",
                    "$ref": "#/$defs/pct"
                },
                "total_pct": {
                    "description": "Percentage of samples in which the function is present anywhere in the call stack, counted once per sample.",
                    "$ref": "#/$defs/pct"
                }
            }
        }
    }
}
```

## 4. Rules the schema can't enforce

- `self_pct` values sum to about 100 across all hotspots, or less if the list is ever capped.
- `total_pct` is always greater than or equal to `self_pct`. `total_pct` values don't sum to anything meaningful, because one sample counts toward every function on its stack.
- Hotspots are sorted by `self_pct`, highest first.
- A hotspot is identified by `(fn, file, line)`. Two hotspots in the same report never share all three.
